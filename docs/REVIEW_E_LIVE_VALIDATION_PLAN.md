| ID | 固定过程 | 核心观察 / 判断 | 每场景 HTTP 上限 |

### E8-U：配对和估算

- 两次用户请求及静态设置在 prepare 前固定；提示不提供目标 usage 或误差答案。实际生产投影如果改写历史，就如实记录 `history_not_append_only`，不能删掉生产任务投影来强造锚点命中。
- 逐请求报告 `estimatedInputTokens`、`rawRequestBytes`、`sdkInputTokens`、原始 provider 输入 / completion / reasoning / cache 字段及各字段是否存在。原始字段缺失保持 null；SDK 默认 cache=0 不能证明没有缓存。
- 估算差 `E - U`、相对差 `(E - U) / U` 只在 `U > 0` 且同调用可核对时计算；有真实兼容锚点才另算 anchored 差。不用会话累计量、包含输出的 total 或另一请求的 usage 顶替。
- **接线通过标准**：请求 / 终态关联无歧义，诊断值符合固定 SDK 归一化规则，无跨会话 / 压缩代次借用；错误、未知和未观测如实输出。没有兼容锚点记 `not_observed`，不算验证了增量准确性。
- 误差仅描述全部有效样本、低估次数和范围，不在看过数据后拟合比例或挑选样本。无预先验证的 tokenizer，不声称实际容量得到认证；本批不据误差大小自动改预算。

### E8-C：防止答案污染的压缩对照

- 公开合成 seed 约 12–20 KiB，包含早期方案、后续否决、未完成步骤及普通背景。确切文本、对话边界、结构化宿主记录、题目、oracle 和 SHA 在离线实现时冻结。历史是测试材料，不冒充真实用户项目或实测网络活动。
- 两个会话从**相同 seed**开始；A 的答复绝不进入 B 的历史、摘要输入、任务目标或工具结果。B 不做额外预问答，摘要 `customInstructions` 也不得夹带 oracle 答案。
- 题目只给固定字段名，要求简短 JSON。预登记十项事实：当前目标仅出计划；只读边界；章节卡尚待人工确认；候选正文尚未验证；最近失败为来源版本不符；“跳过来源核对”的方案已否决；当前来源版本为 v2 而非旧 v1；下一步需回源并按需刷新检查点；一个尚无证据的事实保持未知；写作职能不获得规划目录写权限。具体场景叙述不授予任何实际权限。
- 1/2/3/4/6/10 为关键项，必须全部正确；全部十项都正确才记本场景答案通过。无法解析、不回答、漏项、矛盾均保留，不补问一次直到答对。A 也失败时，不能把 B 的失败单独归因于压缩。
- 原生摘要原文、持久化 TaskContract / progress、保留近期消息、实际传给模型的投影分别保存来源标识。对每项答案注明可能依赖哪一层；原文已重新注入或答案由结构化合同提供，不能算摘要本身记住了它。
- **两个结果分开**：`summaryContentReview` 是对摘要原文的逐项本地审读，需记录依据，尚未审读为 `pending_review`；`systemRecoveryScore` 是 B 实际答题结果。答案正确不自动证明摘要忠实。不得另发模型裁判请求。
- 必须实际发生一次原生 manual compaction，保存 compaction 事件及摘要 request ID；最多两条摘要请求，与普通请求共享额度。多摘要并发 / 终态顺序和每条计量需先离线核验，丢失或无法配对的样本不能补成完整覆盖。压缩前后锚点必须失效，原历史文件保留，Canon 无变化。
- 此处主动手动压缩不是 256K 工作窗口自动触发的验收；未发生的自动 / overflow / 分支压缩标为未测，不靠提高历史体积强迫本批触发。

### E8-R：真实读取轨迹，不虚构节省率

- 只使用独立副本的 `notes/e8-source.md`，v1/v2 各约 1 KiB 且相同字节长度，版本和公开标记不同。oracle 位于模型可读项目之外；所有读路径及内容 SHA 预先登记。
- 第一次提示要求 Agent 实际读取文件；第二次只继续当前任务，观察 Context 自己的来源校验；随后宿主只在该隔离文件上写入 v2，第三次要求根据当前文件作答。修改时间线和写入前后 SHA 记录为宿主测试事件，不当作模型完成的写入。
- 记录 native 工具调用、扩展 `metrics.reads` 按种类分项、逻辑引用、`sourceCache`、每个 Context 的快照及读取失败。只能称“扩展所计 readFile 调用 / 返回字节”，不能称操作系统磁盘 IO、全进程 IO、token 或费用节省。
- **通过标准**：确实有两个引用指向同一来源的 Context，复用不移除校验逻辑；后续 Context 有新的实际来源读取；变更后不能把 v1 凭证视为 v2，最终答案须有新的实际读取支撑。需 refresh 时由 Agent 正常处理，不由测试器伪造新凭证。
- 若 Agent 没产生所需引用、没读取或额度内未完成，记未覆盖 / 任务失败，不能将缓存命中 0 解释为无需优化。E1 的 87-byte 合成历史对照仅作既有机制证据，不与本批不同轨迹相减得出真实节省比例。

## 4. 共用额度与参考费用

| 项目 | 拟定限制 |
| --- | ---: |
| 全批 / 单场景 HTTP 派发 | 24 / 8 |
| 每请求最终序列化输入 | 65,536 UTF-8 bytes |
| 每请求外层保守输入预留 | 65,536 estimated tokens（按字节计，非实际 tokenizer） |
| 每请求输出参数上限 / 安全余量 | 2,048 / 4,096 |
| 全批输入估算预留 / 输出预留 | 1,572,864 / 49,152 |
| 请求 / 单场景 / 全批超时 | 90 秒 / 8 分钟 / 25 分钟 |
| 每个响应字节上限 / 每场景工具派发 | 262,144 / 12 |
| E8-C 原生手动压缩 / 摘要请求 | 1 次 / 最多 2 条（均包含在 24 次内） |
| 批准有效期 | 精确清单 prepare 后 24 小时，限单次使用 |

工作窗口仍为 262,144；`65,536 + 2,048 + 4,096 = 71,680` 小于该窗口。外层字节预留和生产多语言估算器是不同口径，分别记录，不因外层通过就跳过生产预算。若完整工具 schema 或合成 seed 导致 prepare 超限，应在授权前缩小无关合成背景并重新冻结；不能在实测中截断当前请求、改题或临时涨额度。

沿用用户参考价：普通输入 $0.75 / 1M tokens，输出 $3.75 / 1M tokens，缓存输入 $0.075 / 1M tokens。满额预留、全部输入不扣缓存的参考值为：

`(1,572,864 × 0.75 + 49,152 × 3.75) / 1,000,000 = $1.363968 ≈ $1.36`。

这**不是实际预计花费、账单或美元硬限额**。代理内部重试、token 定义及 reasoning 计费不由本地保证；若实际已报告用量超过预留，保留超出量并停止，不能回填成额度内。原始 cache / 必要计费口径不明确时，费用仍为未知，不按零或全部普通输入伪造实付费用。生产诊断的 `costUsd=null` 保持不变。

- 只允许清单指定 endpoint；不重定向、不自动切模型。独立会话关闭 SDK 自动 retry；任何 SDK 内层再次尝试仍由出口门检查并拒绝，不隐式增发。并行产生的原生摘要在 broker 处串行派发且各占一个额度。connectivity 测试若需要，也必须另行入清单，不免费额外发送。

- 格式错误、事实答错、未形成缓存命中或产品侧安全阻断属于场景业务失败 / 未覆盖；在没有安全和传输问题时可继续下一预登记场景。产品安全拦截单独通过，不代表答题或任务完成。
