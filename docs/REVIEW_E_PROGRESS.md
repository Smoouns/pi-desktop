# E5：有界的非权威任务进展（2026-09-25）

本批补 AUD-05 的执行轨迹，不改变 AUD-10 的有效进展停止算法，不引入自由文本记忆、模型裁判或第二套 Agent Loop。

## 验收合同

1. 只由宿主确认的工具结果生成记录，区分实际交付的读取、已确认写入、机械验证、失败及未知结果；不从 assistant 声称“已完成”的文字或摘要推断。
2. 记录绑定项目 / 会话 / 职能 / taskId，随 Pi 活动分支保存和恢复；有数量与字节上限，不保存工具正文、写入内容、原始参数或错误堆栈。旧会话没有记录时明确为空，不回填猜测。
3. 压缩后可看到做过的操作、结构化错误码、来源 / 报告引用及固定恢复提示。全部标为历史、不具权威性；历史 PASS 不是当前 PASS，历史写入成功不是当前内容已满足。
4. 来源失效时显示需要重新核对；Observation 跨进程失效仍回源，不新增持久化正文库。记录不得更新 Canon、验收、来源凭证、Operation Ledger 或完成合同。
5. 最新记录损坏或版本不支持时不回退旧成功；可选进展记录不可用时显示缺口，不改变核心安全门禁或自动重放。迟到 / 跨会话 / 跨任务结果不能污染当前记录。
6. 在完整生产扩展与固定 SDK 隔离进程中验证压缩、冷恢复、失败原因、来源变化、作用域隔离和零重放；使用公开合成项目，不调用真实模型、不控制桌面、不改全局配置。

## 边界

这是结构化的历史导航，不是理解任务的语义摘要，也不是“已排除方案”的推理记忆。缺失或被容量上限淘汰的步骤必须显式标注。模型效果、无效重读收益及语义摘要质量仍需单独授权的真实模型对照；本批不宣称这些效果已验证。

## 实现与使用

- 管理扩展 v23。在更新后的 Desktop 重启 Pi 运行时后生效。`/novel-run-status` 的只读窗口显示最近 5 条历史进展；Agent 的 `get_task_checkpoint` / `get_run_status` 结果有独立 `progress` 字段。状态查询不会恢复任务、写文件或调用模型。
- 使用 Pi 活动分支的 `pi-desktop-task-progress/v1` 自定义记录，不新增自由文本记忆库。宿主记录实际交付的读取范围、确认写入后的 SHA、完整 / 分场验证结果及报告引用、结构化失败码。参数和错误内容仅取摘要，不保存正文、提示词或错误堆栈；assistant 声称通过不能生成凭证。
- 每份记录最多 24 条 / 24 KiB；每条最多 4 个来源、8 个诊断码。发送给模型的视图最多最近 12 条 / 12 KiB，并计入原有预算。`droppedItems`、`omittedFromView`、`omittedSources` 分别标示容量裁剪和引用省略；旧会话不猜测补写。
- 普通继续、原生压缩、冷恢复后按项目 / 会话 / 职能 / taskId 查找活动分支。来源变化只给历史记录附上重新核对提示，不能改变原始结果或跳过重新验证。Observation ID 仍仅是需重新核验的引用，跨进程不可用时回源读取。
- 记录均标为 `historical=true`、`authority=false`、`userAccepted=false`，来源默认 `not_checked_here`，不是当前事实。检查点、写入对账、当前完整验证和人工验收继续各自负责，历史成功不授予权限。修复建议来自固定错误分类，不使用模型推断。
- 可选记录保存失败在当前进程标为 `unavailable`，不回退显示旧成功，也不把已完成的文件写入改成失败。已有损坏 / 不支持版本的最新记录在冷恢复时仍不可用。突然断电或没有成功落盘的步骤无法可靠重建；新进程可能只有较早已存的历史，因此覆盖始终标为 `partial_host_receipts_only`，不声称完整日志。
- 上限约束单份快照与上下文投影，不是整个 Pi 会话文件的磁盘大小；Pi 日志仍追加保存。活动分支超过 10,000 项时此可选视图保守不可用。未覆盖的原生工具错误、发送 / 中断事件不补写猜测，相关原始历史和核心运行状态仍保留。
