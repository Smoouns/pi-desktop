# Phase 3 — 版本感知检查点与压缩验收清单

起点：`f21b2b46a53729ed5722f5b816fe9fd21a447dc9`。按用户授权实现 Phase 3；只使用公共合成 fixture，不修改私人小说、凭据或模型配置。本文件定义实现与自动化验收范围，完成情况另记结果文档。

## 边界与取舍

- 检查点是任务记忆，不是新的 Canon、人工验收或写入许可。保留目标、原始用户约束、来源 path/SHA/范围/authority/temporal、观察 ID、产物版本、未决问题、建议下一步、未完成操作及预算。
- 使用 Pi 的 `appendEntry` 持久化自定义会话记录；只从当前分支恢复，并严格隔离项目、会话和角色。Observation payload 仍不持久化，旧 ID 不能伪装为重启后可读。
- 压缩前先确定性去重/外置工具观察，再保存结构化检查点。保留 Pi 原生 compaction，不替换 LLM、不实现 Agent loop。扩展的 before-compact 返回接口不能修改 customInstructions；检查点独立保存，不能声称已把它注入原生压缩提示词。
- 压缩摘要是未核验叙述，不是事实源。恢复后的模型上下文用当前核验结果与检查点引用约束它；过期摘要不得继续作为有效证据。硬约束不得静默截断，超过上限时明确停止。
- 来源修改/删除、人工验收失效、权限或时态变化时，旧证据失效，写入先阻塞。重新读取有效来源并显式刷新后才更新版本；仅查看状态不能洗白旧证据。文件回滚不等于自动批准继续。
- 保存待写入的指纹与参数摘要，不保存可自动执行的命令；恢复时只读核对，不自动重放写入。无法证明结果的操作必须保守阻塞。
- 继续使用 Phase 2 读取/输出/请求预算，检查点进入独立请求账本。取消及晚到结果不得写入另一会话。
- 不加入 Supervisor、自动三 Agent 编排、向量库或自动 Canon 提取。Phase 2 Google 最终载荷硬闸门仍按既定决定暂缓。

## 必须覆盖的自动化场景

- [x] P3-STORE：严格 schema、内容完整性摘要、容量边界、不可变复制、三次模拟压缩往返约束保持。
- [x] P3-SOURCE：版本/范围/权威/时态/验收改变、删除、读取失败、取消与回滚。
- [x] P3-RESTORE：当前分支恢复、扩展重载及真实 SessionManager 文件重开、项目/会话/角色隔离、损坏记录不回退为旧有效检查点。
- [x] P3-COMPACT：实际 Pi loader 普通及 minified 模式；原生 preparation 与扩展 hook 覆盖压缩前保存、失败取消、压缩后重验，不替换原生压缩算法。
- [x] P3-CONTEXT：失效摘要/观察不作为有效证据；精确保留用户约束；检查点计入预算，超过限额显式停止。
- [x] P3-WRITE：旧证据阻塞写入；重读并刷新后才继续；待操作持久化，丢失回执后的恢复不产生重复写入。
- [x] 回归：生产和测试 typecheck、三轮确定性 Harness、五组领域回归、frontend build、隔离源码验证。

自动化使用无模型的本地合成测试；真实模型效果、原生 Desktop 端到端恢复、远端 CI 必须另行取得证据，不由 hook 测试推断通过。
