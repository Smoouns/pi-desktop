## 实现边界

- Pi 保留模型循环、原生重试、工具分发与压缩。Supervisor 只控制运行边界，不成为第二个 Agent loop，不串联三个职能。
- 状态为 `RUNNING`、`BLOCKED_USER`、`BLOCKED_PREREQUISITE`、`NO_PROGRESS`、`CANCELLED`、`FAILED`、`COMPLETED_CANDIDATE`。完成候选不是用户验收、Canon 晋升或语义正确性证明。
- 第一版使用确定性规则：同一验证对象的正文 SHA、规范化错误和已读版本证据均未改变，连续三次失败则停止。报告时间戳、重复读同一版本、无来源工具文本不计进展。另限制运行轮数、工具调用与验证次数，防止变换错误绕过限额。
- 监管状态只记录范围、计数、摘要与原因码，不保存小说全文或密钥。使用当前 Pi 分支自定义记录持久化；项目/会话/角色/运行代际均隔离。晚到结果不能覆盖新运行。
- 阻塞或停止之后不得因 `agent_end` 自动改成完成。只允许用户显式开始新一轮；恢复仍经 Phase 3 的来源重验及未知结果核对，不重放写入。
- 写作产物需要当前版本的完整机械验证；局部场景 PASS、文字声称完成、模型截断或有未决操作都不能标为完成候选。非写作答复仅表示该轮正常结束，不声称小说通过验收。
- 通过状态查询工具与中文提示暴露停止原因及下一步，不增加人工验收权限。保留 Phase 2 已知 provider 最终载荷硬闸门限制。
