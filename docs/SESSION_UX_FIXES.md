# 会话切换、消息布局与自动命名

日期：2026-09-21。针对 Phase 3 实机验收后反馈的会话与界面体验问题；不修改小说正文、Canon、模型配置或凭据。

## 改动

- 会话启动支持 `--session` 精确恢复，启动前验证文件、启动后核对 session ID，省掉先创建空会话再 `switch_session` 的重复加载。只有已知空临时草稿缺失时才重新创建；历史损坏不回退为空白。
- CLI 更新检查改为后台执行并节流。切换只等待必要的状态和消息读取，不等待强制模型/认证目录刷新；目录使用既有 TTL，手动刷新仍会强制读取。
- 快速 A→B→A、进程重启、过期导航、模型切换及统计刷新都核对请求所属范围，晚到响应不覆盖当前聊天。会话管理页的历史选择与侧边栏共用路由。
- 消息容器解除固有最小宽度，普通文本、长 ID、路径及行内代码允许换行；代码块和表格保留内部横向滚动。
- 调整侧边栏顶部的层叠上下文，避免玻璃效果将工作区下拉菜单限制在资源树图标下方；菜单关闭后不影响项目图标点击。
- Desktop 会话中，未命名会话在首个符合条件的成功回复后后台请求当前模型生成中文标题。仅截取可见用户/助手文本，排除隐藏小说上下文、thinking 和工具内容，并遮盖常见凭据模式；独立请求不进入对话历史。
- 标题调用最多尝试一次，持久化尝试记录，15 秒取消、输出上限 384 tokens；失败不循环重试。手动命名优先，切换会话/模型会废弃旧结果。打开旧会话不会批量调用模型；旧的未命名会话可在下一次成功回复后命名。
- 全局受管扩展默认关闭，只有 Desktop 子进程携带 `PI_DESKTOP_SESSION_TITLE=1` 才启用。完成后通过专用状态事件刷新界面，不显示内部 JSON，不重绘整段历史。

## 验证与边界

- `npm run check`、`npm run check:harness-tests`、`npm run test:harness`、`npm run test:novel-domain`、`npm run build:frontend`。
- Rust `cargo check`。
- `npm run test:chat-layout` 使用本机已有 Chromium 的独立无头实例，覆盖 280/360/600px 的混合中文、长工具 ID、Windows 路径、行内代码、代码块和表格。证据在忽略目录 `artifacts/harness/chat-layout/`。
- `node scripts/test-workspace-menu-layer.mjs` 在浅色、深色主题复现旧版遮挡并验证新样式的命中顺序、菜单选择与关闭后图标点击。使用真实样式的最小浏览器测试页，不等同于原生窗口实测；证据在忽略目录 `artifacts/harness/workspace-menu-layer/`。
- 自动命名使用真实固定 Pi 扩展 loader（源码及压缩构建）和模拟 provider 测试成功、错误、隔离、一次性记账及人工标题优先；没有为本次 UX 测试发起真实模型请求。实际命名会产生一次小额模型调用，其费用依 provider 计价。
- 没有重新操作用户的桌面窗口，也没有声称热切换零延迟或提供未经测量的耗时数字。当前仍读取目标会话历史，不以旧消息缓存替代身份校验；冷启动耗时仍受本机 CLI/扩展数量影响。

## 手动复核

重启 Pi Desktop 的开发进程（包含 Rust 重新编译），在两个已打开会话间切换，再打开一份未加载的历史；检查项目、标题、消息和输入目标一致。缩窄聊天栏，查看长 ID 消息。新建未命名会话完成一轮对话，观察标题后台更新；已有手工标题不应被覆盖。
