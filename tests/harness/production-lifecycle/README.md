# Full production lifecycle acceptance (D)

Run `npm run test:production-lifecycle` from the repository root. This command is offline and does not open or control a Desktop window. CI runs it on Windows/Node 24 and Ubuntu/Node 22, separately from the three-repeat unit/hook Harness.

The worker loads the complete current `NOVEL_TOOLS_EXTENSION_CONTENT` with the pinned Pi loader and uses real `createAgentSession`, `SessionManager`, `prompt`, `compact`, `abort`, `newSession`, and `switchSession`. It does **not** manually emit lifecycle hooks or substitute an alternative supervisor/completion/checkpoint implementation. Native read/write/edit definitions are delegated unchanged through SDK custom-tool wrappers, with counters inside actual dispatch (after the production guard), not at the attempted-call boundary. The installed chapter verifier is the actual repository TypeScript script.

Only model responses, UI callbacks, and the frontend-to-SDK transport are test doubles. The synthetic provider runs the SDK's final-payload callback and obeys cancellation. Its fixed summary exercises native compaction, not summary quality or a real provider's serialization/token usage. `modelCalls=0` refers to real model calls; `syntheticProviderInvocations` is reported separately.

| Group | Direct assertion |
| --- | --- |
| submission-state | Actual composer function → in-memory transport → production input → persisted task; clean user echo and status-summary function. No DOM, Tauri RPC or native UI claim. |
| delivery | Real multi-tool batches, body write, verifier PASS but missing proposal rejects completion; add proposal, compact natively, exit, reopen in a new process, retain ordered task constraints without replay. Changing the card invalidates old verification until explicitly verified again. |
| read-range | Persist only delivered lines 8–9. In a new process, change the source: rereading line 1 cannot refresh 8–9; two relevant single-line reads can. Old Observation IDs do not survive process exit. |
| lost-acknowledgement | Exit **86** inside the native-write wrapper after bytes are written but before SDK tool_result/agent_end. Another process reconciles the dispatched intent; a third observes external B and rejects old A. Exactly one native write across all three. |
| cancel | Real SDK abort before synthetic response/tool dispatch, followed by cold reopen: CANCELLED persists, no file effect or automatic provider call. |
| corrupt-latest | Persist a valid contract, append a deliberately damaged latest record, cold reopen: reject before provider, restore unsent input, do not fall back to earlier success. |
| session-role-isolation | Actual A(write) → B(plan) → A → B switching. Hold an A response until switch aborts it; it cannot dispatch into B. Returning to A yields the exact INTERRUPTED_RUN fence, not automatic resumption. |

| task-progress (E5) | Actual invalid-page error and failing verifier receipts survive three native compactions and cold restart. Corrupt latest progress is unavailable without an older-success fallback or any change to checkpoint/completion gates; a different task starts empty. Delivery also checks exact historical read/write/PASS receipts, post-compaction model context, source invalidation and no replay. Session/role isolation rejects late A receipts in B. |
| effective-progress-stop (E6) | Three actual verifier failures with two unrelated native reads, two unrelated proposal writes and body whitespace churn stop as NO_PROGRESS / UNCHANGED_VERIFICATION at exactly 10 tools, not a hard cap. Pi 0.63.1 enters the provider 11 times: 10 generated replies plus 1 already-cancelled entry that cannot generate a reply or tool. These are not HTTP counts. Writes are sequential, respecting the unresolved-operation fence. Cold restart preserves that terminal with zero replay; explicit input permits one real repair + full verification, yielding candidate completion only. |

Exactly 5 writes / 5 verifications / 11 synthetic provider invocations; no false stop or human acceptance. |

Each run creates `artifacts/harness/production-lifecycle/d-*/summary.json`, per-stage JSON, isolated synthetic projects and disk sessions. Old evidence is not overwritten. Normal child exit is 0; only the intentional lost-ack stage expects 86, and only the precisely checked mutant expects 1. Any other failure makes the suite exit nonzero.

Isolation: whitelist child environment, separate `PI_CODING_AGENT_DIR`, in-memory dummy auth, no skills/home extensions, no active shell tool, network guard inherited by verifier subprocesses, and an `execFile` allowlist for that installed verifier. These are defenses for trusted test code, **not an OS sandbox**. Verify committed fixture and source hashes before/after; the parent checks project boundaries even for the intentionally terminated worker. Only self-created build directories are removed. Synthetic evidence is retained.

Boundaries: explicit manual SDK compaction (auto-compaction disabled in isolated settings), same-project session/role switching, and controlled interruption points. No arbitrary filesystem race/exactly-once guarantee, semantic acceptance, real-model/HTTP experiment, global Pi configuration change, Desktop clicking, or Rust bridge end-to-end claim. Existing frozen evals remain separate; their historical negative cells are not production failures or new acceptance evidence.

E3's separate `npm run test:task-transport-sdk` loads the same complete extension with actual pinned OpenAI/Google clients connected only to a loopback counting server. It verifies pre-send on-disk reservations, native compaction / tree summaries, late serialization inflation, summary budget rejection, corrupted journals, client retries, streamed cancellation and missing usage. Those synthetic SSE/HTTP results are not real-provider quality or billing evidence. See `docs/REVIEW_E_TRANSPORT.md`.

## Separate Windows native check (D-07, manual UI)

This is **not** part of the command above or unattended CI. It requires permission to control the desktop. Do not open real novels or change the user's existing Pi Desktop configuration.

1. Build the current frontend (`npm run build:frontend`), then run `node tests/harness/production-lifecycle/native-prepare.mjs`. It returns a fresh `artifacts/harness/native-desktop/d7-*` path and creates a separate app identifier / `%APPDATA%` directory, two public fixture copies and an isolated agent. It does not launch a window. On this machine it also snapshots the existing global Pi extension hashes; it never writes them.
2. Compile the generated manifest with `cargo build --offline --manifest-path <work>/app/Cargo.toml --target-dir src-tauri/target --features tauri/custom-protocol --bin pi-desktop-d7`. Do not build over a running test executable. The production Rust bridge sources are copied unchanged; test bootstrap/configuration differences are listed in `native-prepare.mjs`.
3. Open only `pi-desktop-d7.exe`. Add the prepared project-a and project-b with the native folder picker. Confirm the selected model is **D7 Synthetic / Desktop Offline**. The wrapper forces this provider, disables home extensions / skills / shell and installs network protection before starting the actual pinned CLI.
4. In A send `D7-READ` (one native read), then `D7-CANCEL` and press Stop before the bounded wait ends. From chapter 002's workflow choose revalidation in the writing role; append `D7-VERIFY` and a read/verify-only instruction, then send. Inspect the real report, candidate state and details; do not click human acceptance or Canon promotion.
5. Close/reopen the isolated app, record the UTC relaunch time, and switch between A's cancelled/general and verified/writer sessions. Observe the status displays without submitting new requests. Open B: verify no stale A status, then send exactly one `D7-READ`. Return to each A session and confirm its own state. Close only the test app.
6. Run `node tests/harness/production-lifecycle/native-audit.mjs <work> <relaunch-ISO-time>`. It checks files, sessions, exact provider/tool counts, current production bytes and no replay after relaunch; each audit writes a new subdirectory. It **cannot** prove UI visibility. Record actual window observations separately, including failures and configuration limits. If the sequence differs, the exact-count audit fails; use a fresh copy rather than deleting evidence or weakening assertions.

Native boundaries differ from the SDK suite: inherited OS environment (not a whitelist), separate app identity/bootstrap and fixture-only Tauri capabilities; global extension/theme installation is denied. Ancillary Desktop version checks are not claimed network-free. No real model calls, production installation/update/theme validation, or hidden fallback to user auth. Test data and private AppData are retained for review; no automatic cleanup. See `docs/REVIEW_D_NATIVE_ACCEPTANCE.md` for the actual run and the separately fixed blank-console startup issue.

Windows command-builder regression: `cargo test --manifest-path src-tauri/Cargo.toml --lib windows_process_tests -- --nocapture`. Two Rust cases now start seven Node fixtures each from console-less parents, query the actual child console handle, and assert command arguments / working directory / environment / pipes. E1 adds absolute batch paths with Chinese / spaces / shell metacharacters, `.bat` and literal CLI arguments, retaining the relative-cwd control. These fixtures load no Pi or model and reuse the lockfile's Koffi. Windows CI is configured to run them; the new E1 changes have local results only, not a new remote-CI or UI screenshot claim. See `docs/REVIEW_E_METRICS.md`.
